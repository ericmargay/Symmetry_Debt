# Self-hosting with Docker

*[Versión en español](../es/SELF_HOSTING.md)*

Symmetry Debt runs anywhere Docker runs: your laptop, a small VPS, a home server. Nothing in it
depends on `aminoacid.com.mx` or on any account of the original developer.

You need Docker with the Compose plugin, a Google OAuth client
([GOOGLE_OAUTH.md](GOOGLE_OAUTH.md)) and, for anything beyond your own machine, a domain with
HTTPS.

## 1. Start it

```bash
git clone https://github.com/ericmargay/Symmetry_Debt.git
cd Symmetry_Debt

./scripts/setup.sh                 # creates .env and generates the secrets
$EDITOR .env                       # APP_URL, AUTH_GOOGLE_ID, AUTH_GOOGLE_SECRET
docker compose up -d --build
```

Open <http://localhost:3000/debt>.

What you get ([`docker-compose.yml`](../../docker-compose.yml)):

| Service | What it is |
|---|---|
| `app` | The application, built from the [`Dockerfile`](../../Dockerfile). Applies database migrations every time it starts, then serves on port 3000. |
| `db` | PostgreSQL 17. **Not** published to the host: only the app talks to it. |
| volume `db-data` | The database. |
| volume `uploads` | Receipts (`/data/uploads` inside the container). |

> **`docker compose down -v` deletes both volumes** — every debt and every receipt. Plain
> `docker compose down` keeps them. Back up before you experiment:
> `scripts/backup.sh --compose` ([BACKUP_AND_RECOVERY.md](BACKUP_AND_RECOVERY.md)).

Useful commands:

```bash
docker compose logs -f app         # start-up, migrations, errors
docker compose ps                  # "healthy" once /api/health answers
docker compose stop                # stop, keeping everything
```

## 2. The settings that matter

All of them are in [`.env.example`](../../.env.example), with comments. The minimum:

| Variable | |
|---|---|
| `APP_URL` | The address people type, **including the base path**, no trailing slash: `https://debt.example.org` or `https://example.org/debt`. |
| `NEXT_PUBLIC_BASE_PATH` | The path part of `APP_URL` (`/` for the root). **Build-time**: see the next section. |
| `AUTH_SECRET` | Generated by `setup.sh`. |
| `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` | Your Google OAuth client. Register `<APP_URL>/api/auth/callback/google` as a redirect URI. |
| `DATA_ENCRYPTION_KEY` | Generated by `setup.sh`. **Back it up**: saved bank details cannot be read without it. |
| `POSTGRES_PASSWORD` | Generated by `setup.sh` for the bundled database. |

Changes to `.env` take effect with `docker compose up -d` (it recreates the container), except
the two build-time settings.

## 3. At the root of a domain, or under a path

The base path is compiled into the app. Changing it means **building again**:

```bash
# https://debt.example.org  → at the root
NEXT_PUBLIC_BASE_PATH=/        APP_URL=https://debt.example.org

# https://example.org/debt  → under a path (the default)
NEXT_PUBLIC_BASE_PATH=/debt    APP_URL=https://example.org/debt
```

Set both in `.env`, then:

```bash
docker compose up -d --build
```

`MAX_UPLOAD_MB` is the other build-time setting.

Both variants were verified with the published image recipe: a `/debt` build answers under
`/debt` (and redirects `/` to it), a `/` build answers at the root.

## 4. HTTPS and a reverse proxy

Do not expose port 3000 to the internet directly. Put a reverse proxy in front that terminates
HTTPS and forwards to the app. Whichever you use, it must:

1. **not strip the path** — with a `/debt` build the app expects to receive `/debt/…`;
2. pass the public **host** (`Host` and/or `X-Forwarded-Host`);
3. pass the public **scheme** (`X-Forwarded-Proto: https`);
4. append the visitor's address to `X-Forwarded-For`.

The app uses the host to accept form submissions only from its own pages, the scheme together
with `APP_URL` to mark cookies `Secure`, and the address for rate limiting.

Once the proxy is in place on the same machine, set `APP_BIND=127.0.0.1` in `.env` and run
`docker compose up -d`: the app then only listens on the loopback interface.

### Caddy (automatic HTTPS)

Ready-to-edit file: [`deploy/caddy/Caddyfile.standalone.example`](../../deploy/caddy/Caddyfile.standalone.example).

```caddy
# At the root of a (sub)domain — build with NEXT_PUBLIC_BASE_PATH=/
debt.example.org {
	encode zstd gzip
	reverse_proxy 127.0.0.1:3000
}
```

```caddy
# Under a path of a site that serves other things — build with NEXT_PUBLIC_BASE_PATH=/debt
example.org {
	@debt path /debt /debt/*
	handle @debt {
		reverse_proxy 127.0.0.1:3000
	}
	handle {
		# …the rest of your site…
	}
}
```

Caddy sends `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto` and `X-Forwarded-For` on its own.
(Only when something else terminates TLS *before* Caddy — as on Railway — do you need
`header_up X-Forwarded-Proto https`; see [`deploy/caddy/debt.caddy`](../../deploy/caddy/debt.caddy).)

### nginx

Snippets: [`deploy/nginx/debt.conf`](../../deploy/nginx/debt.conf) and
[`deploy/nginx/debt-proxy.conf`](../../deploy/nginx/debt-proxy.conf). Inside your HTTPS
`server { … }` block:

```nginx
location = /debt  { proxy_pass http://127.0.0.1:3000; include snippets/symmetry-debt-proxy.conf; }
location /debt/   { proxy_pass http://127.0.0.1:3000; include snippets/symmetry-debt-proxy.conf; }
```

with, in `snippets/symmetry-debt-proxy.conf`:

```nginx
proxy_http_version 1.1;
proxy_set_header Host              $host;
proxy_set_header X-Forwarded-Host  $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_buffering off;            # pages are streamed while they render
client_max_body_size 12m;       # MAX_UPLOAD_MB plus some room
```

Write `proxy_pass` **without** a path after the port, so the request path is passed through
unchanged.

Both snippets were checked against a running container: `/debt` reaches the app, `/debtors`
does not, uploads above the limit are refused by nginx.

### More than one proxy in front

`TRUSTED_PROXY_HOPS` (default `1`) is the number of proxies that append to `X-Forwarded-For`.
With a CDN in front of your proxy it is usually `2` — provided your proxy is configured to keep
the CDN's entry instead of overwriting it.

## 5. Checks

```bash
curl -s https://example.org/debt/api/health            # {"status":"ok"}  (503 if the database is down)
curl -s https://example.org/debt/api/auth/providers     # "callbackUrl" must be exactly what you registered in Google
```

If sign-in bounces back with an error, nine times out of ten `APP_URL` does not match the
address in the browser, or the proxy is not passing the host or the scheme.

## 6. Email, receipts and reminders

- **Email** is optional. `EMAIL_PROVIDER=smtp` with `SMTP_URL`, or `EMAIL_PROVIDER=resend` with
  `RESEND_API_KEY`. Without it, people see their notifications inside the app and invitation
  links are shared by hand.
- **Receipts** are kept in the `uploads` volume. To use an S3-compatible bucket instead, set
  `STORAGE_DRIVER=s3` and the `S3_*` variables. The bucket must be private.
- **Reminders** run inside the server every hour; there is nothing to schedule. An external
  scheduler may also call `POST <APP_URL>/api/cron/reminders` with
  `Authorization: Bearer $CRON_SECRET` — the job never repeats a reminder.

## 7. Updating

```bash
scripts/backup.sh --compose        # always before an update
git pull
docker compose up -d --build
docker compose logs -f app         # watch the migrations
```

Database migrations are applied when the container starts. If one fails the server does **not**
start; the log says why. See "A migration failed" in
[BACKUP_AND_RECOVERY.md](BACKUP_AND_RECOVERY.md).

Running migrations yourself instead: set `SKIP_MIGRATIONS=true` on the container and run
`docker compose run --rm app prisma migrate deploy` when you choose.

## 8. Running more than one instance

A single container is plenty for personal use. If you do scale out:

- run the **same image** on every instance;
- keep receipts in a bucket (`STORAGE_DRIVER=s3`), not on a local disk;
- nothing else is needed: sessions and rate limits live in PostgreSQL, and reminders are
  de-duplicated in the database.

## 9. Without Docker

You need Node.js 24 (22 or later works) and a PostgreSQL database — the project is tested
against PostgreSQL 17.

```bash
npm ci
NEXT_PUBLIC_BASE_PATH=/debt npm run build
npm run db:deploy                  # apply database migrations
npm start                          # http://localhost:3000/debt
```

`npm start` runs `scripts/start-standalone.mjs`: it copies the static assets next to the
self-contained server that the build leaves in `.next/standalone`, loads `.env` (set
`SKIP_ENV_FILES=1` to use only the real environment) and starts it. `PORT` and `HOSTNAME` are
honoured. Plain `next start` is not used, because the app is built in standalone mode.

Run it under a process manager (systemd, pm2…) and behind a reverse proxy, as in section 4.
